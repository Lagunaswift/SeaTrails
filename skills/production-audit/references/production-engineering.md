# Production engineering coverage

Use the [stack profile](stack-adaptation.md) to select the rows that apply to the service under review. A static site can have a CDN and a deploy pipeline without having accounts, workers or a database. A headless service may need the database and worker checks without a mobile layout review.

- Pass each applicable row and its named surface to the owning lens. Links in the **Baseline** column identify the supporting reference. The **New** link opens the check added here. The last column gives the evidence to inspect in this audit.
- Use the [coverage matrix](coverage-matrix.md) for the result. Name the component and evidence inspected. If deployed settings, a required independent report or a representative measurement are unavailable, name the missing evidence in the partial cell. For example, a declared API gateway with no exported origin policy is a partial infrastructure review. Direct origin access remains unknown. For a genuinely absent surface, record the reason in scope.
- File a finding only for an evidenced defect or unmet requirement. Give its location, consequence and smallest corrective change under the lens's existing category and severity rules. Multiple rows can point to one finding. No new report fields or finding IDs are required.
- Review security topics through source, configuration, existing tests and supplied records. Record credential types only. The penetration-testing row reviews independent assurance evidence.

## Standards used for the extended checks

- For passkey ceremony verification and federated subject binding, consult the [OWASP passkey guidance](https://cheatsheetseries.owasp.org/cheatsheets/Passkey_Security_Cheat_Sheet.html) and [OpenID Connect Core, section 5.7](https://openid.net/specs/openid-connect-core-1_0.html#ClaimStability).
- For password verification and salts, consult the [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- For PostgreSQL roles and read/write policy semantics, consult the documentation for the installed major version. See [row security policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) and [CREATE POLICY](https://www.postgresql.org/docs/current/sql-createpolicy.html).
