# Typography Engineering Review

This extension converts the ten "Niche Typography Hacks" screenshot entries (S20.01–S20.10) into **conditional, evidence-based audit probes**. It supplements the existing S17 design review and ANIM engineering review; it does **not** add ten mandatory design features, a lens, report fields, a score or new control IDs. Keep the original brand and existing working typography when a technique does not solve a demonstrated problem.

## Scope, evidence and safety

At Stage 0/1 record the routes/components, supported font files and fallback metrics, languages/scripts, viewport and zoom targets, product typography tokens and user task. Run the probes through code-audit's UI/UX pass and the appropriate Impeccable, accessibility, performance and internationalisation lenses. Include normal/hover/focus states, populated and long content, font-load/fallback, 320px reflow, 200% text resize, and representative supported locales. Check actual DOM text and accessibility tree where content is clipped or replaced.

For every S20 source item, record **assessed with outcome and evidence**, **not applicable with a concrete reason**, or **partial/blocked with missing test/access** in existing website profile topic evidence (primarily layout-features, mobile-accessibility, performance, content-brand or interaction-states). A static screenshot cannot prove cross-browser behaviour, memory use or screen-reader output. A source or design suggestion is not proof of a defect. Retain unresolved required browser/manual checks as partial. Findings use the native owning lens and deduplicate shared causes; no S20 finding prefix or new subject kind is introduced.

## Test matrix and reporting

1. **Baseline:** identify the actual affected text, font, fallback, weight, language, design token, route/component and revision. Compare before/after for each proposed fix.
2. **States:** inspect default, active/selected, hover, focus and loading states where the typography changes during interaction.
3. **Stress:** use long and short text, an acronym, a path/filename extension, accented letters, superscript markers and correct locale content. Try a font missing the expected feature.
4. **Device/adaptability:** check actual supported phone/desktop widths, 200% text resize, equivalent narrow reflow and text-spacing overrides. Do not assume one screenshot covers all viewports.
5. **Accessibility:** verify essential full text and control names remain obtainable without hover-only access; inspect keyboard and assistive-technology behaviour for clipped or generated text.
6. **Evidence:** record the observed defect, impact and condition; show computed style/DOM/browser result and meaningful regression evidence. Source-only work cannot claim visual verification.
7. **Disposition:** KEEP, RESTYLE, REWRITE or REMOVE only when a reason is tied to task clarity, brand, accessibility or measured layout/interaction behaviour. The absence of any one named technique is not itself a failure.

Use the existing 119 website controls and 12 topic records. This extension does not authorise deployment, rebranding or global font changes. Prioritise clipped essential content, inaccurate values, inaccessible interactions and layout instability ahead of optical or punctuation polish.

**Primary sources (checked 17 November 2026):** the MDN pages linked in each probe and [W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) / [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html). Recheck target-browser support before enabling recently introduced CSS properties.
