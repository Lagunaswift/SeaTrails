# Animation Engineering Review

Apply this review to **existing or approved motion** in web interfaces, Canvas/WebGL experiences and browser-based games. It is a specialised review inside the current lenses, **not** a new lens, report format, control denominator or prescription to animate a static website. It expands S17.10/S17.14/S17.18/S17.20 from visual behaviour into code lifecycle, memory, performance and library integration.

## Scope, evidence and ownership

At Stage 0, inventory CSS transitions/keyframes, Web Animations API (WAAPI), requestAnimationFrame loops, scroll/view transitions, JavaScript engines (including Anime.js, GSAP and Motion), and Canvas/WebGL/Three.js scenes **actually in use**. Include dependencies and versions, active routes/components, triggers, intended purpose, owner and expected stop conditions. Check whether an animation is decorative, functional feedback or essential to understanding the state.

Use a real component and an actual supported device or browser. Capture the source revision, route, state, viewport, theme, motion preference, refresh rate and throttling/profile conditions. Record a small set of ordinary and adversarial transitions: start, interrupt, reverse, navigate away, unmount, change breakpoint, background/foreground, and error/retry where relevant. A source review can demonstrate an absent cleanup path, but cannot alone establish a memory leak, GPU usage, smoothness or accessibility in a browser.

For **each ANIM-01 through ANIM-20**, record \`assessed\` with an observed result and evidence, \`not_applicable\` with a product reason, or \`partial/blocked\` with exact missing evidence. Use the existing website profile topic evidence and native finding IDs. ANIM labels provide traceability only; they are **not** 20 new scored controls or an observation subject type. Required untested work leaves the affected topic partial, with \`scope.partial=true\`. Do not invent benchmarks or turn an absent animation library into a defect.

The control IDs below refer to the standalone website brief's existing 119 controls; inside SeaTrails, route each confirmed finding to its **native consequence owner**: \`frontend-robustness\` for incorrect state/races, \`performance\` for measured rendering or resource cost, \`accessibility\` for barriers, \`code-audit\` for correctness, \`impeccable-audit\` for purely visual design-system inconsistencies, and \`release-and-ops\` for version/dependency problems. Merge duplicate root causes and preserve their real severity.

## Library-specific integration review

Use only the technologies detected in the target project. These are **version-qualified examples**, not instructions to install or migrate a library.

- **CSS and WAAPI:** inspect transition/animation event listeners, element identity, fill state and \`Element.getAnimations()\`. \`Animation.cancel()\` aborts playback and can reject \`finished\` with \`AbortError\`; compare \`cancel()\`, \`finish()\` and any \`commitStyles()\` use against the intended final state. Avoid permanent forwards-filling animations when no longer needed. [MDN WAAPI](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API), [MDN cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel).
- **Anime.js:** for **v4**, inspect \`createScope({root, mediaQueries})\`, ownership of timelines and scope \`revert()\` on teardown. \`revert()\` also restores scoped values; choose whether restoration is appropriate for the component. Inspect ticker/engine visibility behaviour and global state. For v3, consult v3's actual API rather than applying v4 code. [Anime scope](https://animejs.com/documentation/scope), [revert](https://animejs.com/documentation/scope/scope-methods/revert).
- **GSAP/ScrollTrigger:** inspect \`gsap.context()\` or React \`useGSAP()\`, selector scoping, \`revert()\`, \`matchMedia()\`, and plugin/ScrollTrigger ownership. Animations initiated later by handlers require appropriate context-safe scoping and cleanup. Check route transitions and refresh after layout changes. [GSAP context](https://gsap.com/docs/v3/GSAP/gsap.context%28%29/).
- **Motion (React):** inspect \`AnimatePresence\` children and stable keys, exit sequencing, nested propagation and \`useAnimate()\` component scoping/cleanup. Test interrupted exit/enter and \`useReducedMotion()\` or the current equivalent. Do not assume unrelated manual listeners are automatically cleaned. [Motion AnimatePresence](https://motion.dev/docs/react-animate-presence), [useAnimate](https://motion.dev/docs/react-use-animate), [reduced motion](https://motion.dev/docs/react-use-reduced-motion).
- **Three.js / WebGL:** removing a mesh from a scene does **not** dispose its GPU-side geometry/material/texture. Track explicit disposal and shared ownership; check render targets, controls and ImageBitmap data, plus renderer disposal at the appropriate lifetime boundary. Use \`renderer.info\` as a clue, not a simple zero-leak oracle, because reusable internal resources may remain. [Three.js disposal](https://threejs.org/manual/pages/how-to-dispose-of-objects.html).
- **Lottie, Pixi, canvas-based libraries and other engines:** inspect their **installed-version-specific** renderer/animation \`destroy\`/\`dispose\` APIs, asset caches, tickers and worker listeners. Do not call a method by name without verifying that API's contract and whether assets are shared.

## Verification playbook

1. **Baseline:** choose a real animation-heavy task and route. Record installed library/version, affected source, normal and reduced-motion visual state, device/browser, CPU/GPU conditions and frame/heap baseline.
2. **Lifecycle:** exercise repeated enter/exit cycles with a stable fixture (for example 20 cycles, adjusted to the feature). Count live timers/listeners/tickers/animations and capture heap snapshots with comparable opportunities for GC. Follow retained-object paths when growth persists. Heap snapshots and some GPU traces require manual DevTools or browser instrumentation; never claim they ran from a source grep.
3. **Race:** start the effect, reverse halfway, navigate away while pending, return and repeat. Assert final DOM/ARIA state, focus, the authoritative operation result and absence of stale callbacks. For transitions tied to remote work, stop the *visual* effect without falsely claiming the request was cancelled.
4. **Pacing:** record a browser performance trace during the intended animation and a heavier state (long list, slow device or CPU throttle), including long tasks, forced layout, paint, layer changes, dropped frames and layout shift. Separate field INP/CLS claims from short lab traces. Do not convert an individual frame spike into a blanket 60fps failure.
5. **Responsive/accessibility:** use supported narrow and wide sizes, zoom, keyboard, motion preference and visibility changes. Ensure stopping motion never leaves content at opacity 0 or blocks interaction.
6. **Report:** for each ANIM label give applicability, method, expected/observed outcome, evidence link, affected route/revision, native owner and a specific remaining limitation. Prioritise actual blocked interaction/data loss and accessibility before cosmetic easing or stagger tweaks.
