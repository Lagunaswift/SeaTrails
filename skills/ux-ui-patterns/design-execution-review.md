# Design execution review

Use these twenty source probes on the selected routes and tasks. They translate the design-terms screenshot into checks on the actual implementation. `S17.01` through `S17.20` identify source coverage; they add no controls, finding prefixes, lenses or score. The existing 119-control mapping remains intact.

Read `production-audit/references/design-review-context.md` for the brief, brand and evidence boundary. Preserve useful conventions and intentional detail. For a style choice, record keep, rewrite, restyle or remove with a page-specific reason. Optional techniques need a supported benefit; absence of animation, OKLCH, tabular figures or a custom combobox is not itself a defect. This reference supplies audit guidance and grants no fix authority.

## Record evidence at the level inspected

For each applicable probe, record the route/component, actor or reading task, state, revision, viewport, supported locale/theme and the relevant source. Note the observation, decision, evidence reference and remaining limitation. A screenshot supports appearance in that state; interaction, assistive-technology and performance claims need their corresponding checks. A preference about appearance or an inferred reading cost cannot establish user preference or conversion improvement.

Link these notes through the existing website topic or optional-feature evidence. Under `assurance_version: 2`, rendered/interactive evidence still requires a completed `web` observation with the existing topic/feature as its subject. Do not invent an `S17` observation-subject kind or mark an unperformed browser check complete. Missing required evidence makes the affected topic partial/blocked under the existing contract.

The table maps likely controls and native owners. Select the owner by the demonstrated consequence and deduplicate one root cause. Visual preferences alone do not create findings; access barriers and incorrect state retain their specialist severity.

## Source probes in screenshot order

| Source probe | Applicability and check/action | Acceptance evidence | Existing controls and native owners |
|---|---|---|---|
| S17.01 Kerning | For prominent text or wordmarks, inspect spacing between specific letter pairs in the actual loaded font. Identify collisions or misleading gaps before adjusting the font feature or asset. Global letter spacing changes more than one pair; preserve approved logo artwork. [D01] | Record the exact text, face, size and rendered before/after comparison where a change is authorised. Pairs remain readable at supported sizes and fallback states; intentional spacing has a stated reason. | BRAND-03, BRAND-04; `impeccable-audit`, with `taste-audit` for brief fit. |
| S17.02 Optical centre | Where an icon or asymmetric mark is meant to appear centred, compare its perceived balance with its container and neighbouring controls. Inspect actual asset bounds and padding before proposing an optical offset. Geometric centring and a fixed pixel nudge are not universal acceptance rules. | Rendered comparisons at relevant sizes show a justified alignment decision. Any adjustment preserves the intended hit area, focus indicator and baseline; approved identity remains recognisable. | BRAND-03, BRAND-04, UX-06; `impeccable-audit`; `accessibility` if the control becomes obstructed. |
| S17.03 Tabular numbers | For changing counters or comparable numeric columns, check whether unequal digit widths impede comparison or move neighbouring content. Consider the font's tabular figures when useful; retain proportional figures where they suit the text. Do not require a monospace font or a font replacement. [D02] | Test different digit widths/counts, signs, decimal/group separators and representative locales. Values and units remain correct, columns compare clearly and updates do not produce the identified movement. Confirm the font supplies the feature; equal digit widths alone do not reserve space for a longer value. | BRAND-03, UX-03, PERF-04; conditional OPT-09. `impeccable-audit`, `performance`, `internationalisation`. |
| S17.04 Layout shift | On loading and subsequent interaction, trace unexpected movement to fonts, media, inserted content or changing dimensions. Reserve space or change insertion behaviour where it causes the observed problem. An intentional layout change needs context rather than automatic removal. [D03] | Capture the affected route/state and a trace or recording, including slow resource delivery. Separate load-only lab evidence from lifetime/field CLS. Verify the repaired reading/tap target and use PERF-01's measurement conditions and thresholds. | PERF-01, PERF-02, PERF-04, UX-03; `performance`, with `frontend-robustness` for incorrect state. |
| S17.05 Tracking | Inspect overall letter spacing for the text role, case, font and writing system. Repair collisions or excessive spacing only where they impair the stated reading task or conflict with the brand. Connected scripts may need different treatment. [D04] | Test actual content and supported scripts, then applicable WCAG text-spacing overrides. No clipped labels, missing content or lost controls. The override values test adaptability; they do not prescribe the authored spacing. [D05] | BRAND-03, BRAND-07, A11Y-06; `impeccable-audit`, `accessibility`, `internationalisation`. |
| S17.06 Optimistic update | Where the UI changes before confirmation, assess whether the action can safely appear provisional. Distinguish pending from committed outcomes. Inspect rejection, lost responses, repeated actions and out-of-order results; reconcile an unknown write outcome before retrying or claiming rollback. Optimism is optional. [D06] | Safe fixtures compare UI state with authoritative state after success, rejection and timeout. Recovery preserves later work and creates no duplicate effect. Money/access success is never inferred from the optimistic display. | UX-05, UX-10, REL-01, REL-02, REL-08; conditional PAY-01/PAY-02. `frontend-robustness`; `code-audit` for money/access boundaries. |
| S17.07 X-height | When text appears small or changes markedly during font loading, inspect the actual lowercase height and glyphs, not just the nominal font size. Review fallback metrics and legibility in supported scripts. `font-size-adjust` is one possible remedy when suitable, not a required feature. [D07] | Compare primary/fallback text at the real size, zoom and container width. Characters remain distinguishable, text stays available and font substitution does not introduce clipping or the identified layout instability. Record any readability inference honestly. | BRAND-03, A11Y-06, PERF-04; `impeccable-audit`, `accessibility`, `performance`. |
| S17.08 Touch target | Measure applicable pointer targets and neighbouring hit areas. WCAG 2.2 AA generally requires 24 × 24 CSS pixels, with defined exceptions; evaluate the actual spacing, inline, equivalent-control, user-agent or essential exception before failing a target. Larger important controls can improve comfort. [D08] | Record target geometry and any relied-on exception. Test touch and keyboard with overlays and zoom; enlarged hit areas neither overlap neighbours nor leave the visible control unresponsive. A universal 44-pixel AA rule is incorrect. | A11Y-08, UX-03, UX-06; `accessibility`, `mobile-and-responsive`. |
| S17.09 Leading | Inspect line height and paragraph separation for the actual face, size, content and reading task. Check diacritics, superscripts and mixed-size inline content. Relative/unitless line height can help inheritance; choose it for the implementation, not as a score. [D09] | Test default reading layout and the applicable combined spacing overrides in D05, plus zoom/reflow. Lines and controls remain available without overlap. Do not turn the WCAG override test into a universal default line-height rule. | BRAND-03, A11Y-06, UX-03; `impeccable-audit`, `accessibility`. |
| S17.10 Origin-aware animation | If an existing transform explains a trigger/panel relationship, inspect its origin when the panel opens, closes or flips near a viewport edge. Check whether the motion explains that relationship. A centred origin or instant state change may be appropriate. [D10] | Record the interaction at relevant placements and during scrolling/resizing. The final position, hit area and focus agree; reduced-motion behaviour preserves the operation. Do not add animation merely to demonstrate an origin. | A11Y-04, A11Y-10, UX-06, BRAND-03; `impeccable-audit`, `frontend-robustness`, `accessibility`. |
| S17.11 OKLCH | Where OKLCH is used or proposed for a real palette problem, inspect resolved colours, theme roles, supported syntax and display/fallback behaviour. Its lightness channel is not a WCAG contrast ratio. Keep a working existing colour representation unless changing it solves an evidenced problem. [D11] | Check actual foreground/background combinations with a suitable contrast method and the applicable exceptions. Compare supported themes and fallback environments; semantic states remain distinct and the intended palette survives conversion. [D12] | BRAND-03, A11Y-07, PERF-06; `impeccable-audit`, `accessibility`; `frontend-robustness` for unsupported syntax. |
| S17.12 Widow | For headings or paragraphs with an awkward short last line, first establish a reading/hierarchy problem. Review copy, container width and wrapping before inserting hard breaks or non-breaking spaces. In fragmented print/column layout, CSS `widows` controls lines at the top of a fragment; it does not fix every lone final word. [D13] [D14] | Recheck supported widths, zoom, fallback fonts and locales. Preserve meaning and wrapping access; no new overflow or hidden words. A deliberate short line can remain. Test print/columns only where those outputs exist. | BRAND-03, BRAND-05, UX-03, A11Y-06; conditional OPT-19. `impeccable-audit`, `mobile-and-responsive`. |
| S17.13 Safe area | For edge-aligned or fixed/sticky UI, inspect cut-outs, rounded corners, browser chrome and virtual-keyboard conditions. Use safe-area environment values where appropriate; they do not prove every keyboard or viewport case is handled. [D15] | On recorded supported devices/orientations, the final action, focused field and dismissal controls stay visible and reachable. Include edge cases with notices/CTAs; name real-device checks that emulation cannot establish. | UX-02, UX-03, A11Y-04; conditional OPT-18. `mobile-and-responsive`, `accessibility`. |
| S17.14 Stagger | Where elements enter sequentially, assess whether the sequence helps orientation and whether delay grows with list size. Check first use, repeat navigation and realistic item counts. Keep important actions available; existing simultaneous or instant rendering is acceptable. | Record the sequence and total wait under stated conditions. Keyboard focus never lands on an invisible staged control, required content cannot remain hidden, and reduced motion reaches a usable final state. Report measured cost rather than a universal timing limit. [D16] | A11Y-03, A11Y-10, UX-05, PERF-03, PERF-04; `impeccable-audit`, `accessibility`, `performance`. |
| S17.15 Line length | For sustained reading, inspect the actual measure with the chosen font, language, text size and viewport. Adjust container width only for a demonstrated reading or layout issue. Short labels and dense comparison tables need different treatment from prose. | Record representative lines and rendered conditions; text reflows at narrow widths and under enlargement. A preferred character range is design guidance. WCAG 1.4.8's line-width mechanism is AAA, not a universal AA character cap. [D17] | BRAND-03, BRAND-05, UX-03, A11Y-06; `impeccable-audit`, `taste-audit`, `accessibility`. |
| S17.16 Affordance | For a control or apparently interactive surface, compare its visual cue and label with its actual action. Check persistent cues on touch, native semantics, accessible name, focus and disabled prerequisites. A particular button style, cursor or icon library is not mandatory. | Complete the action by supported input methods. Appearance does not promise an unavailable operation, and state changes have usable feedback. Record inferred discoverability separately from observed user confusion. | UX-04, UX-06, A11Y-03, A11Y-05, BRAND-03; `code-audit`, `accessibility`, `impeccable-audit`. |
| S17.17 Combobox | Where a combobox exists or an approved selection/search task needs one, identify editable versus select-only behaviour and popup type. Prefer an existing/native control when it meets the need. Inspect name, expanded/value/selection states, focus and the appropriate APG keyboard pattern; listbox and dialog popups differ. [D18] | Exercise typing/paste and platform editing keys where editable, selection, Escape, Tab, pointer and screen reader. Test no results, asynchronous stale results and invalid values as applicable. The committed value matches the displayed selection; no focus trap or forced custom widget. | UX-04, UX-06, A11Y-03, A11Y-04, A11Y-05; conditional OPT-10. `accessibility`, `frontend-robustness`, `code-audit`. |
| S17.18 Interruptible animation | If motion is present, rapidly reverse/repeat the action, navigate away and change the relevant layout or motion setting mid-flight. Check cleanup and completion/error handlers. With Web Animations, cancelling can reject the current `finished` promise; handle expected cancellation. [D19] | The latest requested state wins without a stale overlay, disabled control, jump to an obsolete state or lost focus. Essential operation never depends solely on an animation finishing. Stopping visual motion does not claim cancellation of a server operation. | UX-05, UX-06, A11Y-04, A11Y-10, REL-01; `frontend-robustness`, `accessibility`; `impeccable-audit` for visual treatment. |
| S17.19 Progressive disclosure | For an existing disclosure or a complex task, identify which secondary detail can wait and which prerequisites, fees or error information must be available now. Check the disclosure cue, state, keyboard operation and return path. Dense useful information can remain visible; an accordion is optional. [D20] | Complete novice and repeat-task probes using realistic data. Needed options remain discoverable, validation reveals relevant hidden errors, and expanding/collapsing preserves safe input and focus. Record unsupported assumptions about user needs as limitations. | UX-04, UX-06, UX-10, A11Y-04, CONV-02; conditional OPT-11/OPT-16. `code-audit`, `accessibility`, `frontend-robustness`, `taste-audit`. |
| S17.20 Shared element transition | If an existing transition links the same item across views, verify identity, destination state and navigation semantics. Check failed/rapid navigation, focus/scroll restoration, reduced motion and unsupported-browser fallback. Any snapshot effect must preserve the real accessible interface. [D21] | The same content/action remains available when the effect is skipped or unsupported. Check stale snapshots and, where used, duplicate `view-transition-name` values. For View Transitions, `skipTransition()` skips the animation while the view update still runs; test that distinction. [D22] | UX-02, UX-06, A11Y-04, A11Y-10, PERF-04, PERF-06; `frontend-robustness`, `accessibility`, `performance`; `impeccable-audit` for visual continuity. |

## Existing coverage to reuse

Use `nielsen-usability-review.md` for the task rationale and `forms-and-input.md` for form recovery. `frontend-robustness/references/optimistic-and-races.md` owns optimistic state and race handling. `performance/references/measuring-performance.md` and `performance/references/rendering-path.md` own measured layout/rendering effects. `mobile-and-responsive/references/viewport-and-rendering.md` owns safe-area/viewport behaviour. The accessibility references own text adaptation, target exceptions and assistive-technology verification.

The probes add specific cases to those reviews. Generic table-count, typography or animation preferences in a craft reference cannot establish a defect without the product context and evidence required here.
